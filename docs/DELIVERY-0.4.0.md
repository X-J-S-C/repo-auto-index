# 交付单 · repo-auto-index 0.4.0 · 2026-10-14

> 一张纸。上半说清改了什么、为什么，下半照着做就能验。

## 一、这一版给用户的新承诺

**第一次用的人知道下一步做什么；老手能在面板里直接挑要投给哪个会话。**

0.3.x 把索引链路变得可见（六环体检卡），但还留了两个洞：

1. **新人不知道从哪开始**。面板只写「未读到索引：可能不存在，也可能存在但读取失败」，
   把「没装 AOCI」「装了没写条目」「文件读失败」三种处境混成一句。新人看完不知道要装什么。
2. **投递是盲投**。0.3.2 让去向可见了，但只能跟着"当前选中的会话"走；用户在面板里
   想换目标，得跑到聊天区去切。而实测确认**能列出全部会话**，所以可以在这里直接选。

### 新人指路（第 1 项）

判断依据只有一件事：`.aoci/config.json` 在不在（后端 `aociInit`）。

- **不在**（没初始化）→ 三步指引：装 AOCI-CODE → `aoci init` / `aoci scan` → 重启 Agent 让条目落地
- **在但没条目**（已初始化）→ 说明条目由 Agent 写，不该再让用户去装

面板「索引」页与「预览」页都改了文案。旧的那句含糊话全部去掉。

### 会话选择器（第 2–5 项）

```
目标会话  [标题]  [id]  [切过去看]  [选会话]
         ↓ 点「选会话」展开
[3 个会话，其中 2 个属于本仓 · 上限 200]
[过滤框]
  ▌本仓的会话一     C:\...\atlas-workspace      [已是目标] [跳过去]
  ▌本仓的会话二     C:\...\atlas-workspace\sub  [设为目标] [跳过去]
    别的仓的会话     C:\...\other-repo          [设为目标] [跳过去]
```

左侧色条 = 属于本仓。手动点「设为目标」后进「已指定」模式，聊天里切会话不再覆盖它；
但仍可再点「选会话」换回别的。

## 三、口径定案：session:list 能列全部（文档说不行）

**官方文档 `APPS.md:832` 写着**：

> `session:list` 同样只看得到归属自己的会话。不填不等于看全部，返回的永远只是归属你自己的那些会话。

**实测不是这样。** 本机探针（`scope: "all"` + `app/sessions.read`）拿回 **364 条**会话，
带 `title` / `sessionId` / `cwd` / `agentId`。宿主实现读起来也是这个意思，它按 `scope === "all"` 放行。

```
{ "ok": true, "total": 364, "matched": 178, "error": null }
首三条：索引仓库界面第一性分析 / 评估 answer-me-with-html / REA 代理配置（cwd 均在本仓）
```

**结论：文档是契约意向，宿主实现才是当下事实；两边冲突时以实测为准。**
这一版的功能就建立在这个实测结论上。

## 六、本轮抓到的两个真 bug（写测试时发现）

不是"测过了没问题"，是**测试把 bug 抓出来了**，两条都在面板选择器里：

1. **`APP_UI_SCOPE_REQUIRED`**：挂官方 Button 时行还没插进 DOM，
   那一刻按钮没有 `data-hana-app-ui` 祖先。改为先 `appendChild(row)` 再 `mountInto`。
2. **过滤不生效**：`mountAppUi` 是异步渲染，挂完立刻 `querySelector` 拿不到 input，
   监听器绑到了 `null` 上。改用事件委托挂在容器上。

两条都是"看起来会工作、实际不会"的类型，只有真跑起来才暴露。

## 七、遗留

- **「本仓优先」的排序离线台覆盖不到**。排序在真后端 `index.js` 里，离线台的 mock
  走硬编码顺序，所以 `probe-session-picker` 只验了面板侧的渲染与交互。那条排序靠
  真机实测（364 / 178，前三条均 inRepo）。要让它也进回归，得给 mock 加一层排序模拟。
- **「AOCI 装没装」仍读不出来**。App 没有 `app/process.spawn`，跑不了 `aoci --version`；
  连接器配置在宿主自己的数据目录下，宿主拒绝与 HANA_HOME 重叠的读根。所以指路里只能写
  「装 AOCI-CODE」，不能替他检测装没装。
- **会话选择器上限 200 条**。本机 364 条会话已超，列表只取前 200（本仓优先排序之后再截），
  所以"别的仓"那部分可能不完整。要全量得加分页。
