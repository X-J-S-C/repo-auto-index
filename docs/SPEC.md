# repo-auto-index 面板 · 第一性原理规格 v0.1（UI 侧）

## 0. 硬事实基线（从 index.js / manifest.json 读出的，不是假设）

| 事实 | 值 | 出处 |
|---|---|---|
| 扫描执行模型 | 同步阻塞。`startScan()` 未 detached 时 `await runScan()` 全部走完才返回，因为 execute/handler 返回后 `callToken` 失效（trace 实证：顶层一次 OK，子目录全拒 `app_resource_call_token_invalid`） | index.js `startScan` 注释与实现 |
| 状态真相源 | `dataDir/projects.json`（原子写：`.tmp` + rename） | `writeRepos` |
| 任务 | 只做进度投影与打断旗，不做鉴权载体 | `registerHandler("repo-scan")` |
| 索引位置 | 只读仓库根目录下 `aoci.code.txt` / `aoci.meta.txt` / `aoci.txt`，**不递归子目录** | `readIndexFile` |
| 条数口径 | `countIndexEntries` = 三文件里 `name[TAG]:` 形状的行数，即**条目数**，与 `aoci status` 的 `index_entries` 同口径。旧口径（合并非空非 `#` 的行数，含 `===` 卷头）保留为 `countMergedLines`，界面不再显示 | `countIndexEntries` |
| 已验证样本 | 740 文件 / 76 目录 / 0 拒绝 / 392 条目（473 合并行） | 真机验证 |
| 进度更新粒度 | 每 `PROGRESS_EVERY=200` 个已扫描条目写一次盘 | `onTick` |
| 文件上限 | `SCAN_FILE_CAP=20000`，触顶立即返回并置 `capped:true`，计数变**下限** | `walkCount` |
| 排除项 | 23 个目录名（`node_modules` `.git` `dist` `build` `target` `.next` `coverage` `tmp` `uploads` `backup` `backups` `artifacts` `.output` `__pycache__` `.venv` `venv` `.pytest_cache` `.mypy_cache` `.ruff_cache` `.tox` `.nox` `htmlcov` `.aoci`）+ 所有点文件（`.aoci` 例外但实际仍被目录排除） | `EXCLUDE_DIRS` |
| 权限 | `app/resources.read` / `app/tasks.manage` / `app/tools.expose-to-model`。写入 dataDir 走 node fs，不占资源令牌 | manifest.json |
| 一仓一索引 | 索引=各仓自己的 aoci 文件，插件不建大库；语义条目永远由 Agent 经 aoci 链路写 | 设计约束 |

### 0.1 三个计数各自的语义（这段决定所有文案）

| 字段 | 定义 | 能否当分母 |
|---|---|---|
| `progress.total` | **已发现的文件数**，单调递增，扫描结束前永远不是终值 | 不能。它是"目前为止找到多少文件"，不是"一共要扫多少" |
| `progress.scanned` | **已处理的条目数** = 文件 + 目录，≥ total | 不能。与 total 口径不同（含目录） |
| `progress.dirCount` | 目录数，从 1（根）起算 | 精确性依赖 `entryIsDir`；该启发式在缺元数据时按"名字里有没有点"猜 → 无扩展名的文件会被算成目录 |
| `progress.denied` | list 失败的目录数 | 只在 done 分支落盘；canceled 分支**丢失** |
| `index.entries` | 三文件里 `name[TAG]:` 形状的行数（条目数），与 `aoci status` 同口径 | 与文件数无比例关系 |
| `index.entryLines` | 三文件合并后非空非 `#` 的行数（旧口径，含 `===` 卷头）。仅供对照历史数字 | 同上 |

**推论（写进实现规约）：面板禁止出现任何百分比进度条。** 没有分母。扫描态只允许"不确定动画 + 双计数器"。现有 `bar((total)/max(1,scanned,total))` 是把"文件占已处理条目的比例"伪装成完成度，实测值会单调下降，属于编造，必须删除。

## 1. 用户目标 → 界面义务的翻译

| 用户目标 | 界面必须给出的东西 | 失败的样子（要避免） |
|---|---|---|
| 知道有何仓 | 一份可扫视的仓列表，每行自带最关键状态 | 只给名字，要点进去才知道死活 |
| 每仓何状态 | 六态之一，且态内附"这个状态是什么时候定的" | 写"就绪"但其实是上次扫描的快照 |
| 正在发生何事 | 扫描中的计数器 + 打断入口 + 本轮起点时刻 | 转圈动画，不知道动了没有 |
| 能打断 | 红色打断钮，扫描态常驻（列表行内 + 详情区），一键生效，落盘可查 | 打断钮藏在详情里、列表进不去 |
| 能验结果 | 每个数字附**采集方式与时刻**；能一键拿到 projects.json / trace 路径自己去查 | 只有数字，无法对账 |
| 能信 | 数字不明就说"不明"；受阻/触顶/快照/历史值全部显式打标；失败只记录错误不产生数字 | 权限没放行时显示"就绪 · 0 文件" |

## 2. 状态机

### 2.1 仓库级状态（后端 `status`）

```
(登记写盘) → scanning ──walk 完 + 读索引──→ done
                │                            (denied>0 → done(受阻)，capped → done(触顶))
                ├─ 用户打断 / 取消旗 ──→ canceled（保留部分计数，denied 丢失）
                └─ 抛错 / 建任务失败 ──→ error（带 error 文本，progress 保留）
任意终态 ──rescan──→ scanning（重新同步跑一遍）
```

### 2.2 UI 六态（每块都要能落到其中之一）

| 态 | 判定依据 | 视觉语言 |
|---|---|---|
| **空** E | 无数据可显示（未登记任何仓 / 无索引文件 / 无命中 / 无 trace 行） | 直接说"没有 X"，并给下一步动作，不画空图表 |
| **加载** L | 请求在飞，值未知 | 骨架/占位灰条；**禁止显示 0 或上一轮的值冒充当前值** |
| **扫描** S | `status==="scanning"` | 不确定动画 + `已扫描 N 条目 · 已发现 M 文件 · 目录 D` + 红色打断钮 |
| **就绪** R | `status==="done"` 且 `denied===0` 且 `capped!==true` | 终值 + `finishedAt` + 口径脚注 |
| **出错** F | `status==="error"` 或 HTTP `ok:false` 或响应体校验失败 | 赭红块 + 原始 error 文本 + 可复制 + 重扫出口 |
| **打断** C | `status==="canceled"` | 明确写"已打断"，计数全部标为"部分/下限"，无 entries |

**两个必须存在的子标记（不是第七态，是态内徽标）**

- `受阻`：`done` 但 `denied > 0` → 计数不是全仓真值，只是"读到的那部分"
- `触顶`：`capped === true` → 数字是下限，真实值 ≥ 显示值
- `可疑`：`scanning` 但 `progress.phase === "done"` 或 `updatedAt` 距今超过阈值（见 §7.2）→ 幻影扫描，提示重扫

### A. 总览行（仓库列表）

**回答的问题**：我有几个仓？每个仓现在能不能用？哪个正在动？哪个要我去看一眼？

**数据来源**：`OV`（一次性拿 `dataDir` + `repos[]`）。逐行打断用 `CAN`。

**最小字段（每行只允许这些，多一个都是噪音）**

| 字段 | 取值 | 口径/可信条件 |
|---|---|---|
| 名称 | `repo.name \|\| repo.id` | 可截断，title 给全名 |
| id | `repo.id` | slug，等宽小字 |
| 状态徽标 | 六态 + 子标记 | 见 §2.2 |
| 文件数 | `progress.total` | `done && !denied && !capped` 才显示裸数；否则 `≥N（触顶）` / `N（受阻）` / `部分 N（打断）` / `—（未清点）` |
| 索引条目 | 优先 `RD.index.entries`（实时），未取到时 `repo.index.entries`（快照） | 见 §3.B4 的双来源规则 |
| 定态时刻 | `finishedAt \|\| updatedAt` | 相对时间（"3 分钟前"）+ hover 给 ISO |
| 行内动作 | 扫描中→红色打断钮；终态→无（保持行干净） | 打断一键，无二次确认（可恢复：重扫即可） |

**汇总行（列表顶部或系统行，二选一，不要两处）**

- `共 N 个仓` + 各态计数 `就绪 a / 扫描中 b / 已打断 c / 出错 d`
- 文件总数：**只在所有计入的仓都是 `done && denied===0 && !capped` 时才给**；否则输出 `N 个仓已就绪，合计 X 文件（另有 M 个仓未计入：受阻/触顶/打断/出错）`。禁止给出"合计"却悄悄漏掉不可信的仓。

**六态要点**

- 空：整页空态（§3.D），不画列表骨架
- 加载：`OV` 在飞 → 骨架行 3 条，状态位显示"—"
- 扫描：该行不可点"重扫"（禁用），行内打断可用；行右端显示 `已扫描 N`
- 就绪：裸数 + `finishedAt`
- 出错：行徽标赭红，副行截断显示 `error` 首行
- 打断：徽标灰，副行"已打断 · 部分 N"，提供重扫（放进详情，行内只放徽标）

**鲁棒性**

- `repos` 为空数组 ≠ 出错。`OV` 返回 `ok:true, repos:[]` 必须走空态，不是错误态
- `OV` 返回 `ok:false`（500）→ 整页错误态，显示 `error` 原文 + `dataDir` 路径
- 单行渲染异常（字段缺失/类型不对）只降级该行（显示"该行数据不可读"），不整页崩

### B1. 身份头

**回答的问题**：我现在看的是哪个仓？它在磁盘上的哪里？什么时候登记的？

**数据来源**：`OV`（`name/id/dir/gitUrl/registeredAt/updatedAt`），`RD.repo` 同名覆盖。

**字段与要求**

| 字段 | 要求 |
|---|---|
| name | 主标题 |
| id | 等宽小字；这是所有路由的 `:id` |
| dir | 等宽、可换行、可复制按钮。**这是"一仓一索引"的物理锚点**：索引就在这个目录下 |
| gitUrl | 有则显示（可复制），无则整行不渲染，不显示 `null` |
| 登记/更新 | `registeredAt` / `updatedAt`，相对时间 + ISO |

**鲁棒性**：`dir` 缺失（老数据）→ 显示"目录缺失，请重扫或重新登记"，并禁用一切依赖 dir 的操作。

### B2. 进度 + 打断（本面板的核心）

**回答的问题**：现在在动吗？动到哪了？怎么让它停？

**数据来源**：`OV.progress`（扫描中每 1–2s 轮询），打断用 `CAN`。

**内容**

1. 状态行：`扫描中 · 自 <startedAt>` + 已运行时长
2. 双计数器（等宽、右对齐）：
   - `已扫描条目 N`（=`progress.scanned`，含目录）
   - `已发现文件 M`（=`progress.total`）
   - `目录 D`（=`progress.dirCount`，标注"根计入 1，无扩展名文件可能误判为目录"）
   - `读不到 K`（=`progress.denied`，扫描进行中**不显示**，因为该值要结束才落盘；显示"结束才知"）
3. 不确定进度条（横向流动，无百分比）
4. 阶段：`progress.phase`（`walk` / `done`）。`walk`=还在走目录树；扫描态出现 `phase:"done"` 即"可疑"标记来源
5. 红色打断钮（`■ 打断扫描`），旁边一行小字说明真实语义：
   > 停在当前目录批次边界，最长等待一次目录列举。已清点的部分保留，绝不半截写状态。停了可重扫。

**打断的三段反馈（必须）**

| 阶段 | 表现 |
|---|---|
| 请求在飞 | 按钮禁用 + `打断中…` |
| 已落盘 | `已打断 · <时刻>`，计数标"部分"，出现 `↻ 重新扫描` |
| 无响应 | 若 `CAN` 超时/断连：**不当作失败**，转继续轮询 `OV` 最多 5 次。仍非 canceled 则显示"打断请求已发出但未确认，可再点一次"，按钮恢复可用 |

**鲁棒性**

- `status !== "scanning"` 时打断钮不出现（避免把已完成的仓误打成 canceled）
- 扫描态不允许同时存在两个 rescan：按钮禁用
- 打断后如果 `index.hasIndex` 为真，补一句：`打断前索引已读完，数值可能已完整`

### B3. 统计

**回答的问题**：这个仓有多大？清点可信吗？

**数据来源**：`OV.progress.total/scanned/dirCount/denied/capped` + `RD.index.entries`

**四个数字 + 三条口径脚注（常驻小字，不可省）**

| 数字 | 显示 | 不可信条件 → 显示 |
|---|---|---|
| 文件 | `N` | `denied>0` → `N（受阻，非全仓）`；`capped` → `≥ N（触顶 20000）`；`canceled` → `部分 N（下限）`；`error` → `未获得（保留上次：N）`；`scanning` → `已发现 N（进行中）` |
| 目录 | `D` | 同左；额外脚注：无扩展名文件可能被计入目录 |
| 读不到 | `K` | `canceled` → `未统计`；其余 → 裸数；`K>0` 时整块降级为受阻 |
| 索引条目 | `E` | 见 B4 |

**禁止的派生指标**

- ❌ 完成度百分比（无分母）
- ❌ "索引覆盖率 = E / 文件数"（E 是行数不是条目数，两者无比例关系）
- ❌ "平均每个文件多少行"之类

**受阻态必须显式说明因果**：
> 有 K 个目录列举失败（多为 `app/resources.read` 未放行或权限不足）。已显示的文件数只覆盖能读到的部分，**不是这个仓的真实规模**。

**鲁棒性**：`denied` 为 `undefined`（canceled/老数据）→ 显示"未统计"，**绝不显示 0**。

### B4. 索引文件区

**回答的问题**：这个仓有没有索引？索引是哪个文件？多少行？这个数字是刚才读的还是旧的？

**数据来源**：**双来源，必须区分**
- 实时：`RD.index` → `{ file, entries, hasIndex, preview }`，每次打开详情/刷新都重新读盘
- 快照：`OV` 里 `repo.index` → `{ file, files[], entries, hasIndex }`，只在**上次 done 扫描**时写入。`canceled/error` 时 merge，**不会清空** → 快照可能是很久以前的

**显示规则**

| 情况 | 显示 |
|---|---|
| 实时 `hasIndex: true` | `主索引 <file> · 条目 <E> · 实时读取于 <now>` |
| 实时 `hasIndex: false`，快照 `hasIndex: true` | 赭黄：`本次未读到索引（上次快照 <E> 行，<快照时刻>）。可能是文件被删/改名/读失败` |
| 两者都 false | `未读到索引` + 展开说明：`只查仓库根目录下 aoci.code.txt / aoci.meta.txt / aoci.txt，不递归子目录` |
| 多文件 | 候选顺序固定 `aoci.code.txt → aoci.meta.txt → aoci.txt`，合并为一个虚拟文档；主名取第一个存在的 |

**P0 诚实性要求**：`readOneFile` 失败与文件不存在在后端不可区分（都返回 null）。所以 **`hasIndex:false` 时禁止写"该仓库还没有 aoci.txt"**，只能写"未读到索引：可能不存在，也可能存在但读取失败"。

**计数口径脚注（常驻）**：
> 条目数 = 三个 aoci 文件里 `name[TAG]:` 形状的行数，不算空行、注释行与 `===` 卷头。与 `aoci status` 的 `index_entries` 同一口径。条目由 Agent 经 aoci 链路创作，插件只清点。

**鲁棒性**：`entries` 缺失 → `—`，不得写 0。

### B5. 预览区

**回答的问题**：索引里到底写的什么，我先肉眼看一眼对不对。

**数据来源**：`RD.index.preview` —— **前 60 条非空非 `#` 行**

**必须标注的三件事（否则用户会误读）**

1. `前 60 条目（已过滤空行、注释与卷头）`，若实际返回 60 条 → `（可能还有更多，共 <E> 条）`
2. **预览没有行号**。后端返回的 preview 是过滤后的数组，行号信息已丢失 → 每行**不得**编造行号
3. 预览的"第 1 行"**不等于** `aoci.code.txt` 的第 1 行，它是合并虚拟文档过滤后的第一条

**呈现**：等宽、单行省略（不换行）、容器可滚动、可全选复制。加一个 `复制全部预览` 按钮。

**六态**

- 空：`hasIndex:false` → 整个区块替换为 B4 的引导文案，不画空框
- 加载：`RD` 在飞 → `正在读本仓索引…`（不显示上一仓的残留内容）
- 扫描：`未读索引（扫描结束后才读）`
- 就绪：60 行预览
- 出错：读失败 → `索引读取失败：<error>`
- 打断：`未读索引（已打断）`，若快照有旧值 → `上次快照预览（<时刻>）` 并整块加灰底 + "历史值"标签

### B6. 只搜本仓

**回答的问题**：这个仓的索引里有没有某个东西？在哪一行？

**数据来源**：`SE`，参数 `q`（必填）、`limit`（1–100，默认 20；面板传 30）

**匹配语义（必须写在输入框下方，一行）**
> 子串匹配，忽略大小写，不分词、不支持正则。范围＝本仓三个 aoci 文件合并后的文本。**只搜本仓，不跨仓；不搜源码与文件名。**

**行号口径（关键）**：`hits[].line` 是**合并虚拟文档**的行号，**不是某个具体文件里的行号**。UI 必须写成 `合并文档第 N 行`，禁止写 `aoci.code.txt:12`。

**结果呈现**

| 项 | 规则 |
|---|---|
| 标题 | `搜本仓 · <q> · <file> · 命中 <k> 行` |
| 截断 | 当 `k === limit` → 改为 `至少 <k> 行（已截断至上限 <limit>，请细化关键词或调大 limit）`。**禁止把 `total` 当总命中数** |
| 行内容 | 后端截断 240 字符 → 显示时标注"行内容最多显示 240 字符" |
| 空查询 | 前端直接不发请求，提示"输入关键词" |
| 无索引 | 后端返回 `file:null, hits:[]` → 必须显示"本仓还没有可搜的索引"，与"搜了但没命中"区分开 |
| 作用域标签 | 输入框必须显示当前作用域：`本仓：<name>` |

**已知缺口（写在区块脚注）**：本仓**文件清单**检索不存在，搜索只作用于 aoci 文本。

### B7. 错误 / trace

**回答的问题**：它为什么说失败？我怎么自己查出真相？

**数据来源**：`repo.error`；trace 落在 `dataDir/traces/<repoId>.jsonl`，事件：`walk-start` / `list-ok` / `list-denied`

**显示**

1. 错误块（仅 `status==="error"` 或请求失败时出现）：原始 `error` 文本、等宽、可复制、`↻ 重新扫描` 出口
2. 受阻明细：`K 个目录读不到（明细见 trace）`
3. trace 区：给出路径 `dataDir/traces/<id>.jsonl` + 复制按钮；请求新增路由 `GET /repo/:id/trace?tail=200`（否则"能验结果"做不到）

**六态**：空（无 trace 文件 → "尚未开始过扫描"）/ 加载 / 扫描（`trace 正在追加，扫完再看`）/ 就绪（tail 200 行 + 路径）/ 出错 / 打断（trace 保留可看）

### B8. 操作区

| 动作 | 路由 | 前置 | 后置与说明 |
|---|---|---|---|
| `↻ 重新扫描` | `RE` | 仅 `done/canceled/error` 可用；`scanning` 禁用 | **同步阻塞**：请求会一直挂着直到扫完（这是设计，不是 bug） |
| `■ 打断扫描` | `CAN` | 仅 `scanning` 可用，红色 | 见 B2 |

### D. 登记入口（空态与常驻共用同一个组件）

**数据来源**：`ADD`（`POST /repo/add`，body `{dir, name?}`）

**表单**：目录路径（等宽输入）+ `登记并扫描` + 可选名称

**三条前置说明（必须在按钮旁边）**

1. 插件只登记**已存在**的目录；不私自 clone。目录不存在 → `400 目录不存在：<dir>，先 clone 再登记`
2. 同一目录重复登记 = 更新，不新增
3. 克隆在宿主侧做，或让 Agent 调 `repo_index_add({dir, gitUrl})`

**空态文案要点**：`一仓一索引，不跨仓；语义索引走 AOCI 链路，插件只清点`。

## 4. 关键交互规程：同步阻塞扫描下的两条通道

后端 `/repo/add` 与 `/repo/:id/rescan` 都是同步阻塞，**请求挂到扫描结束才返回**。

**规程**

1. 用户点"登记"/"重扫" → 前端**立即**发 POST，**不 await 它的结果来更新界面**
2. 同时启动轮询 `OV`（1s 间隔）。仓库记录在 POST 之前就已写盘，所以 `OV` 立刻能看到 `status:"scanning"`
3. POST 返回 `ok:true` → 仅作"已受理"确认；**忽略其 `repo` 体**（它恒为 `status:"scanning"`, `progress{0,0}`）
4. POST 超时 / 断连 / 网络错误 → **不当作失败**。保持轮询：若 `OV` 显示该仓在扫描或在 X 秒内变为终态，就当成功
5. 轮询停止条件：该仓 `status !== "scanning"`，或连续 3 次 `updatedAt` 未变且已超过阈值 → 标"可疑"

## 7. 轮询与活性判定

### 7.1 轮询表

| 触发 | 目标 | 频率 | 停止 |
|---|---|---|---|
| 页面加载 | `OV` + `RD`(选中仓) | 一次 | — |
| 任一仓 `scanning` | `OV` | 1s | 无 scanning 仓后降为按需 |
| 手动刷新 | `OV` + `RD` | 一次 | — |
| 用户切换选中仓 | `RD` | 一次 | — |
| 面板重新可见/获得焦点 | `OV` | 一次 | — |
| 空闲 | 不轮询 | — | — |

### 7.2 "可疑"判定（幻影扫描）

`status === "scanning"` 且满足任一：
- `progress.phase === "done"`
- `updatedAt` 距今 > 2 × 该仓上次已知扫描时长且计数器 3 次轮询未变
- `taskId` 为 null

→ 显示赭黄条：`这个"扫描中"可能已经不真实了（后端状态未落盘）。点重新扫描重跑一遍。`

## 9. 一句话验收标准

把每个仓的每一行数字都配上"它从哪来、什么时候采的、在什么条件下不可信"三件事，同时保证扫描态永远有红色打断钮、永远没有百分比进度条。做不到这三件事的板块，宁可不显示。
