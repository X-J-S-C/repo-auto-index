## 2. 本次修掉的三处规范缺口

### 缺口一：六个工具全部缺 `sessionPermission`

工具注册的权限档在 v2 里是**必填语义**：未声明的默认按 `review` 处理，
即每次模型调用都进审阅。对本 App 这种「只动自己 dataDir」的工具是过重的。

按 `APPS.md`「sessionPermission」定的档（`readOnly:true` → read；`auto:"allow"` → routine；
其余 → review）：

| 工具 | 档 | 依据 |
|---|---|---|
| `repo_index_add` | `auto: "allow"` | 只写自己的 `dataDir/projects.json` 并起一个扫描任务，不碰用户文件 |
| `repo_index_debug` | `readOnly: true` | 只 `resources.list` 拿形状，零写入 |
| `repo_index_list` | `readOnly: true` | 只读自己的登记表 |
| `repo_index_status` | `readOnly: true` | 只读登记表 + 仓库里的 aoci 索引文件 |
| `repo_index_cancel` | `auto: "allow"` | 只改自己 dataDir 状态、停自己起的任务 |
| `repo_index_search` | `readOnly: true` | 只读本仓 aoci 索引文本 |

**没有**用 `kind: "plugin_output"` 或 `external_side_effect`：前者是给走 `stageFile` 交付
产物的工具用的（本 App 不产会话文件），后者是访问外部 provider/网络/真实世界副作用的工具
（本 App 的 `network` 是 `null`，一行业务代码不出站）。

### 缺口二：`ui/CONTRACT.md` 与实现严重脱节

这份文件自称「面板的**唯一契约**。改代码前先改这里」。三向比对（HTML 全部 `id="…"`
× `panel.js` 全部 `byId("…")` × 契约表）实测结果：

- 契约表里 **25 个 id 在 `panel.html` 中根本不存在**（`b-identity` `b-progress` `add-form`
  `add-dir` `add-name` `add-submit` `err-text` `err-retry` `repolist-mount` `summary-mount`
  `sys-mount` `copy-dir` `copy-git` `id-dir-row` `preview-foot` `search-form` `search-submit`
  `refresh-btn` 等）
- `panel.html` 有 **26 个 id 未被契约记录**（`board` `detail` `side-count` `bar-hint`
  `stats-note` `index-time` `search-semantics` `err-detail` 及全部 `-mount` 挂载点）
- **「关系」页签（`data-pane="relations"` / `data-block="graph"` / `graph-view` /
  `graph-note` / `graph-mode-mount`）完全没有契约条目**，而它是 2026-10-13 傍晚新增的第五个页签
- 契约声明的 `data-mount` 机制**在实现里不存在**（0 处使用），实际约定是 id 以 `-mount` 结尾

已按实测把 §2 表重建为与实现一致，并补上校验方式（三向比对）。§1 硬规则第 4 条、
§5 挂载规则里关于 `data-mount` 的表述一并改正。

## 4. 官方 `--smoke` 在本机跑不通（已定案为环境问题，非 App 缺陷）

现象：`--smoke` 报 `SMOKE_UI_BLANK` / `SMOKE_UI_ELECTRON_FAILED` / `SMOKE_UI_ENTRY_FAILED`
/ `SMOKE_SDK_HANDSHAKE_MISSING`，`Electron exited 4294967295`。

定案过程（四组对照，每组都可复现）：

1. **基线对照**：昨天打包的 0.1.2 zip 跑出**逐条相同**的失败清单 → 与本次改动无关。
2. **全新最小 App 对照**：临时造了一个几十行的 App（一个 `hana.ready()`），
   `backend` 正常 `loaded`，UI 段报**完全相同**的失败 → 与本 App 代码无关。
3. **Electron 环境对照**：自解压的 Electron 44 与 40 都能正常渲染自建页面
   （实测 `document.body.innerText` 拿到文本），说明 Electron 本身没坏。
4. **参数形态定位**：把官方 driver 的 `--url <含 :// 的值>` 后面再跟任何参数，
   Electron 立刻退出且**一行 JS 都不执行**（用 1 行 `console.log` 的最小文件复现）；
   把 `--url` 挪到最后一位，官方 driver 立刻跑通并返回 JSON。

**结论**：`app-validation-electron-driver.mjs` 被 smoke 调用时参数顺序为
`driver.mjs --url <url> --profile-dir <dir> …`，`--url` 的值含 `://` 且后面还有参数，
Electron 在这一形态下启动失败。这是**宿主/Electron 侧的参数解析问题**，
不是 App 包的缺陷。切换 Electron 版本（44 / 40）均复现。

**可用的替代验证路径**（本次已用，全部通过）：

| 验证面 | 方式 | 结果 |
|---|---|---|
| 静态（目录） | `validate-app.mjs --dir --json` | `ok:true` 0 error |
| 静态（归档） | `validate-app.mjs --archive --json` | `ok:true` 0 error |
| 后端真实执行 | `--smoke` 的 backend 段（AppHost 跑 `apply()`） | `status: "loaded"`，`error: null` |
| 后端路由（真实宿主） | `GET /api/apps/<id>/routes/health` | `200 {"ok":true}` |
| UI 页面（真实宿主） | `GET /api/apps/<id>/ui/panel.html` | `200`，7482 bytes |
| UI 资源（真实宿主） | `GET …/ui/assets/panel.js` | `200`，含 BUILD 标识 |
| 离线渲染回归 | `_tmp/repo-panel-preview/` 六态 + 五页签 | 全绿，零报错 |

**未覆盖**：Electron 隔离环境下的页面启动与 SDK 握手（`--smoke` 的 UI 段）。
在参数形态问题排除前，这条无法在本机取得正面证据。不宣称已通过。

## 5. 2026-10-13 追加：页签高亮指示器不跟随（已修）

**现象**（用户报告）：「点各个选项，为什么那个图标不会跟着移呢」——内容确实切换了，
但页签上的高亮/下划线指示器留在「概览」不动。

**根因（实测确认，不是推断）**：官方 `Tabs` 是**纯受控组件**。
`app-ui.js` 内部用的是 `controllableStrict({ controlled, default, ... })`，
选中指示完全由传入的 `value` 决定；原生点击只触发 `onChange`，不自已改选中态。

而 `renderTabs()` 的签名去重写死成常量 `"1"`：

```js
if (!changed("tabs-mount", "1")) { applyTab(); return; }
```

`state.tab` 变化后签名仍为 `"1"`，`changed()` 永远返回 false，
于是**永远不会把新的 `value` 回传给已挂载的控件**。指示器卡在首次挂载那一项。

**实测证据**（离线台，两次运行结果完全一致）：

| 动作 | 内容 `[data-pane]` | 官方 Tabs `aria-selected` |
|---|---|---|
| 初始 | overview:shown | `true,false,false,false,false` |
| 点「索引」 | index:shown ✔ | `true,false,…` ✘ 不动 |
| 点「关系」 | relations:shown ✔ | `true,false,…` ✘ 不动 |

独立最小探针进一步证明了机制（`tabs-probe.html` + `probe-tabs-update.mjs`）：
纯受控组件在不回传 `value` 时，连原生点击也不会改变指示器；
一旦调用 `handle.update(props)`，指示器立刻跟随。

**修法**（三处）：

1. 新增 `mountOrUpdate(hostId, name, props)`：已挂着同一个控件就调句柄的
   `update(props)` 就地更新，不 `destroy` + 重挂。官方提交的句柄确实带
   `update`（`app-ui.js` 导出处可查：`{ control, element, update, destroy }`）。
   就地更新还顺带避免了重挂带来的闪烁与丢焦点。
2. `renderTabs()` 签名改为 `state.tab`（原来写死 `"1"`），
   并在 `onChange` 里回掉 `renderTabs()` 让受控值回传。
3. `renderGraphModeTabs()` 同步改用 `mountOrUpdate`，保证降级切清单时选中项也跟上。

**回归**（全部通过，零报错）：

- 六态：`ready` / `scanning` / `canceled` / `error` / `empty` / `blocked` → `errors: (none)`
- 五页签逐个切换：四个 `[data-pane]` 正确互斥
- 指示器跟随：点「索引」→ aria 移「索引」；点「关系」→ aria 移「关系」
- 搜索「aoci」仍可命中
- 静态校验：`ok:true`，0 error / 1 warning（预期项）

**同类排查**：另外 13 处 `mount()` 全是 `Button` / `EmptyState` / `ErrorState`，
无受控 `value`，不受此问题影响；两处 `TextInput` 只传 `label` / `placeholder`，
也是非受控的，且挂在 `empty-mount` 签名下（空态不轮询），不会丢输入。

## 6. 2026-10-13 追加：卡片化（「卡片即一切」落地）

### 6.1 起点诊断

改造前这个 App **零卡片能力**：没有 `messageRenderers`、没有 `hana.emit`、没有 storage。
唯一一张卡是 `realization: "page"` 的整页卡（工作台面板），扫描结果全锁在面板里。
对照 Hana Agent Showcard 的三条原则（回答变成应用 / 双方都改得动 / 能递出手），三条都不成立。

### 6.2 已确认的宿主契约（附证据锚点）

全部来自真实源码，不是推断。详版见 `ui/CARD-DOCTRINE.md` §2 与 `_tmp/card-recon/FINDINGS-A.md`。

| 事实 | 锚点 |
|---|---|
| 聊天流卡走工具返回值 `details.card`，宿主自动包装成 `plugin_card` | `bundle/index.js` 函数 `Xon` / `Z_t` / `bCr` |
| `details.card` 字段白名单：`cardType` 必须 `iframe`/`webview`；`route` 非空且 `/` 开头；`aspectRatio` 是**数字**不是字符串 | `plugin-stream-card-registry` 校验函数 |
| `description` 模型侧可见，宿主把它 append 进可见文本 | `bundle/index.js` 两处 `appendVisibleDetail` |

| `APP_UI_SURFACE_PATH_RE` 只匹配 `/api/apps/<appId>/ui` 前缀，`_surface/<token>` 段不影响 appId 解析 | App 自己的 `ui/assets/sdk.js` |
| 流内卡 slot = `"card"` | 桌面端 `PluginStreamCard` 显式传 `slot:"card"` |

### 6.3 做了什么

三路并行施工（各自独占文件，互不越界）：

- **卡片页面**：新增 `ui/report.html` + `ui/assets/report.js` + `ui/assets/report.css`。自取数据（先 `/overview` 再 `/repo/:id`），不依赖 URL 参数也能工作。

### 6.4 收口时抓到的隐患（已修）

**同步器的文件清单是写死的白名单**，只有 6 个文件。新的 report 三件套不在里面，同步器会**静默跳过**，安装目录实测确实缺这三个文件。

这与之前页签 bug、以及「有时新有时旧」是同一类病根：**本该由事实驱动的清单被写死，改一处忘一处就静默失效。**

已改成**派生式**：受服务文件 = `index.js` + `manifest.json` + `ui/` 下除 `*.md` 外的全部文件。真理源从「人手维护的清单」换成「目录本身」。托管集从 6 个增至 17 个，顺带补回一批一直被白名单漏掉的文件（`app-ui.css`、`app-ui.js`、`cover.png`、`sdk.js` 等）。

### 6.5 顺带解释清「有时新有时旧」的完整机制

实测：reload **前** `/api/apps/cards` 只返回 1 张卡，reload **后**变 2 张；而静态资源（`ui/report.html` 等）在 reload 前就已是 200。

原因是宿主有**两套时钟**：

- `ui/` 静态资源是**实时读盘**
- 卡片注册表是**装载时缓存**

所以同步器把文件推过去不够，`reload` 才能让卡片注册表刷新。两件事都做齐才算真生效。

### 6.7 面板投递（方案 A）已全通

权限经用户授权后开启（`app/sessions.read`、`app/sessions.manage`、`app/session.start-turn` 三个新词已入账本）。

**一个必须记录的设计要点**：`session:send-custom` 回包的 `entryId` **可以为 null，而且那不是失败**。
2026-10-13 对照实验定案：

| 目标会话状态 | 回包 | `mode` |
|---|---|---|
| 空闲 | `{ok:true, entryId:"2f6d0e8f"}` | `notifyOnly` |
| **正在流式** | `{ok:true, entryId:null, pending:true}` | **`followUp`** |

流式时消息排进当前回合，尚未落成独立条目，所以没有 entryId。**判定成功必须用 `ok`，不能用 entryId 的有无**。

初版后端把 `entryId` 为 null 当失败报 502，是误判（子助手 impl-D 交付时自己就标注了这个疑点，实测坐实）。已修为：判 `ok`；`entryId` 缺失时回 `pending: true` 并把 `mode` 一并告知，面板显示「已送达（对方正在生成，卡排在当前回合）」。

**投递落下的条目实证**（从目标会话 jsonl 取出）：

```json
{
  "type": "custom_message",
  "customType": "app:repo-auto-index/scan-report",
  "content": "扫描报告：Atlas Workspace（atlas-workspace）\n状态：done\n...",
  "display": true,
  "details": { "hanaAppCustomCardSource": "eyJ..." },
  "id": "2f6d0e8f"
}
```

`customType` 被宿主按规矩盖了命名空间前缀，`display: true`，来源证明由宿主签发，`id` 就是回包里的 `entryId`。
